3. How YouTube API Services are used
   (the three items in your notice)
------------------------------------------------------------
A) Live-stream broadcast data
   GET https://www.googleapis.com/youtube/v3/liveBroadcasts
       ?part=id,snippet,status&mine=true&broadcastType=all&maxResults=50
   UI: module YOUTUBE ЕФІР (YouTubeStreamSettingsWindow)
       title, description, privacyStatus, lifeCycleStatus,
       scheduledStartTime, liveChatId,
       watch URL https://www.youtube.com/watch?v={id}
   Poll loop: YouTubeService.PollLoopAsync selects lifeCycleStatus=live
   Optional update:
   PUT liveBroadcasts?part=snippet,status

B) Live statistics
   GET videos?part=liveStreamingDetails,statistics&id={broadcastId}
   UI: main console YouTube viewers (concurrentViewers) and likes
       (likeCount) plus LIVE indicator
   Implementation: YouTubeService.UpdateStatsAsync

C) Real-time chat integration and moderation
   GET liveChat/messages?part=id,snippet,authorDetails&liveChatId=...
       uses nextPageToken and pollingIntervalMillis
   POST liveChat/messages?part=snippet          (send)
   DELETE liveChat/messages?id=...              (delete)
   POST liveChat/bans?part=snippet              (timeout 600s or permanent)
   DELETE liveChat/bans?id={banId}              (unban, session ban id)

   Chat UI shows authorDetails.displayName, message text, and the
   author’s channel URL https://www.youtube.com/channel/{channelId}.

   Ban / timeout / unban confirmation (Required Minimum Functionality):
   - Target YouTube channel: {displayName}
   - Target channel URL: https://www.youtube.com/channel/{authorChannelId}
   - Acting YouTube account: {channels.list mine=true title}
   - Acting channel URL: https://www.youtube.com/channel/{mineId}

   Implementation:
   YouTubeService.ReadChatAsync / SendMessageAsync / DeleteMessageAsync
   BanOrTimeoutAsync / UnbanUserAsync
   AppServices.BuildYouTubeModerationPrompt
   MainWindow context menu

Methods we do not implement and do not claim:
liveStreams.list, liveChatMessages.streamList, liveChatModerators.*

5. Quota request
------------------------------------------------------------
Current default allocation: 10,000 units/day
Requested quota: 100,000 units/day

While a broadcast is live the client polls about every 5 seconds:
  liveBroadcasts.list          (~1 unit)
  videos.list                  (1 unit)
  liveChatMessages.list        (5 units)
≈ 7 units / 5 s ≈ 5,040 units per live hour.
One 8-hour live day ≈ 40,000 units, plus insert/ban/update/channels.list.
100,000 units/day covers one long live day with headroom.

This quota is requested only for the authenticated creator’s own live
broadcasts, statistics, chat, and moderation.
