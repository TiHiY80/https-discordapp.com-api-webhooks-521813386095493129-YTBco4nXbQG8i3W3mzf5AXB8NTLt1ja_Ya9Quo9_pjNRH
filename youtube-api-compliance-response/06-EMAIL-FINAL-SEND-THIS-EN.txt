3. How YouTube API Services are used
   (matches the three items in your notice)
------------------------------------------------------------
A) Live-stream broadcast data
   - liveBroadcasts.list (mine=true, part=id,snippet,status)
     Returns the creator’s broadcasts. The client shows title,
     description, privacyStatus, lifeCycleStatus, scheduledStartTime,
     liveChatId, and the watch URL https://www.youtube.com/watch?v={id}.
   - A connected poll loop uses the same method to detect the live
     broadcast and attach its liveChatId.
   - liveBroadcasts.update (part=snippet,status) can update title,
     description, scheduled start, and privacy of that same broadcast.

B) Live statistics
   - videos.list (part=liveStreamingDetails,statistics&id={broadcastId})
     The client displays concurrentViewers and likeCount on the main
     console next to the YouTube LIVE indicator.

C) Real-time chat integration and moderation
   - liveChatMessages.list (part=id,snippet,authorDetails)
     Polling uses nextPageToken and pollingIntervalMillis.
     The UI shows authorDetails.displayName, message text, role, time,
     and the author’s channel URL (https://www.youtube.com/channel/{id}).
   - liveChatMessages.insert — send a text message as the signed-in creator
   - liveChatMessages.delete — delete a selected message
   - liveChatBans.insert — temporary timeout (600 seconds) or permanent ban
     using bannedUserDetails.channelId
   - liveChatBans.delete — remove a ban created in this session
     (ban id returned by insert is stored in memory)

Required Minimum Functionality for ban / unban / timeout:
- Confirmation dialog shows the TARGET channel display name and the
  TARGET channel URL.
- The same dialog shows the ACTING YouTube account title and the
  ACTING channel URL (from channels.list mine=true).
- Chat rows identify the author by display name; the channel URL is
  available on the row tooltip.

Methods we do not implement and do not claim:
- liveStreams.list
- liveChatMessages.streamList (we use official list + poll)
- liveChatModerators.*

5. Quota request
------------------------------------------------------------
Current default allocation: 10,000 units/day
Requested quota: 100,000 units/day

Justification from the shipping poll loop (YouTubeService.PollLoopAsync):
While a broadcast is live the client, about every 5 seconds, calls:
  liveBroadcasts.list          (~1 unit)
  videos.list                  (1 unit)
  liveChatMessages.list        (5 units)
≈ 7 units / 5 s ≈ 5,040 units per live hour.

One 8-hour creator live day ≈ 40,000 units, plus
liveChatMessages.insert, liveChatBans.insert/delete, liveBroadcasts.update,
and channels.list. 100,000 units/day covers one long live day with headroom
and does not include search.list or videos.insert.

This quota is requested only for the use case above (the authenticated
creator’s own live broadcasts, statistics, chat, and moderation).
